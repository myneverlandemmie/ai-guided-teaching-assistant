# V0.2 Implementation Plan / V0.2 实施计划

## 1. Purpose / 文档目的

本文件用于规划“智学导评 V0.2”的实施步骤，作为后续 Codex 施工、Git 提交、案例材料整理和阶段验收的依据。

This document defines the implementation plan for V0.2 of the AI Guided SQL Assessment Platform. It will guide Codex development, Git commits, case material preparation, and staged acceptance.

## 2. Current Version Goal / 当前版本目标

V0.2 的目标是在半个月内完成一个可演示、可部署、可申报案例的教学闭环系统。

本文件是早期实施计划记录，当前真实基线以 `docs/requirements/v0.2-scope.md` 和 `docs/project/current-implementation-status.md` 为准。当前代码已推进到 V2 教师端主流程；作业批阅、学生端和学习通 API 仍为预留或后续探索方向。

核心主线为：

- 课程计划上传；
- 自动拆解课次；
- 教师上传课次材料；
- AI 生成知识主干、小测题、分层导学案；
- 学生查看导学案；
- 作业批阅预留；
- 教师复核边界设计；
- 教师复核；
- 学生查看反馈；
- 系统生成学习总结。

V0.2 focuses on SQL / MySQL teaching. Python grading and OCR screenshot correction are not part of the core scope.

## 3. Development Environment / 开发环境

当前施工环境采用：

- 开发施工：WSL / Ubuntu；
- 浏览器测试：Windows；
- 案例演示：阿里云 ECS；
- 教师本地体验：Windows 单机模式；
- 真实课堂使用：教师或学校私有部署。

## 4. Implementation Phases / 实施阶段

### Phase 1: Documentation and Project Skeleton / 第一阶段：文档与项目骨架

目标：

- 建立项目英文目录结构；
- 建立双语 Markdown 文档规范；
- 初始化 Git 仓库；
- 明确 V0.2 功能边界；
- 明确三层使用模式；
- 准备 Codex 施工提示词。

验收标准：

- `git status` 显示工作区干净；
- `README.md`、`docs/requirements/v0.2-scope.md`、`docs/requirements/three-tier-usage-model.md` 已完成；
- `docs/prompts/codex-build-prompt.md` 可用于 Codex 施工。

### Phase 2: Course Plan Import / 第二阶段：课程计划导入

目标：

- 支持上传 `.xlsx` 授课计划；
- 解析周次、课次、学时、教学内容、教学用具、作业、备注；
- 从教学内容中提取课次编码与课次标题；
- 展示解析预览表；
- 支持教师确认、编辑或跳过课次；
- 将确认后的课次保存到数据库。

验收标准：

- 能上传样例授课计划；
- 能解析出 28 个计划课次；
- 能在页面中查看解析结果；
- 能确认生成正式课次。

当前状态：已实现。

### Phase 3: User, Class, and Demo Accounts / 第三阶段：用户、班级与演示账号

目标：

- 实现教师登录；
- 创建“演示班级”；
- 创建演示学生账号；
- 预留正常班级和学生账号管理功能。

验收标准：

- 教师能登录；
- 能查看演示班级；
- 能看到演示学生列表。

当前状态：未实现。当前代码暂用 demo course / demo teacher 作为开发临时上下文，不作为最终试用方式。

### Phase 4: AI Generation Workflow / 第四阶段：AI 生成链路

目标：

- 封装统一 AI 服务；
- 支持 DeepSeek V4 Flash 默认调用；
- 支持 DeepSeek V4 Pro 备用；
- 支持 Mock AI 模式；
- 生成知识主干；
- 生成三层小测题；
- 生成 A/B/C 分层导学案；
- 所有 AI 输出必须可编辑、可保存、可追溯。

验收标准：

- 无 API Key 时可用 Mock AI 模式演示；
- 有 API Key 时可调用真实模型；
- 教师可以编辑 AI 生成内容；
- 教师确认后才能发布给学生。

当前状态：部分实现。已实现 Mock AI 知识主干生成、编辑和保存；尚未接真实 AI API，尚未生成小测题和导学案。知识主干生成前会对材料中的学校、教师、班级等行政信息做基础过滤，但原始课次材料内容仍保留。

### Phase 5: Reserved Assignment Review / 第五阶段：作业批阅预留

目标：

- 教师创建 SELECT + WHERE 作业；
- 后续可探索数据库类作业提交；
- 系统执行 SQL；
- 支持 SQLite 兼容演示模式；
- 支持 SELECT、WHERE、AS、简单计算字段；
- 生成初步批阅结果。

验收标准：

- 学生能提交 SQL；
- 系统能判断正确、错误和语法异常；
- 教师能查看系统初评结果。

当前状态：未实现。

### Phase 6: Teacher Review and Student Feedback / 第六阶段：教师复核与学生反馈

目标：

- 教师查看提交草稿；
- 教师修改得分和评语；
- 教师确认发布反馈；
- 学生查看最终反馈。

验收标准：

- 自动批阅结果不会直接作为最终结果发布；
- 教师确认后学生才能看到反馈。

当前状态：未实现。

### Phase 7: Learning Summary / 第七阶段：学习总结

目标：

- 生成学习总结；

验收标准：

- 每个演示学生可生成一份学习总结；
- 学习总结语言具体、温和、可执行。

当前状态：未实现。

### Phase 8: Deployment and Case Materials / 第八阶段：部署与案例材料

## 8.1 Add-on Prototype / 加分原型与数据标注开端

V0.2 的施工优先级仍然是：

1. 完成 SQL 主线闭环；
2. 完成课程计划上传与课次拆解；
3. 完成导学案、课前学情测试、教师复核边界和使用说明；
4. 如时间允许，补充 Python 基础题批阅 MVP；
5. 同步建立学习错误数据标注字段和演示样例。

Python 批阅 MVP 不得影响当前教师端主流程。它不是完整 Python 自动批阅系统，只能作为后续探索方向。

### Phase 9: Python Grading MVP Add-on / 第九阶段：Python 基础题批阅加分原型

目标：

- 支持单文件 `.py` 或在线粘贴代码；
- 支持简单输入输出题；
- 使用固定测试用例；
- 捕获 `stdout` 和 `stderr`；
- 设置运行超时；
- 初步识别基础错误类型；
- 自动批阅结果必须经过教师复核；
- 将错误类型和教师修正反馈沉淀为学习错误数据。

适用内容：

- `print` 输出；
- `input` 输入；
- 变量赋值；
- 基础数据类型；
- `if` 条件判断；
- `for` / `while` 简单循环；
- `def` 函数入门；
- 形参与实参；
- 输入输出格式；
- 简单字符串与数字处理。

明确不做：

- 多文件项目；
- 第三方库；
- 图形界面；
- 网络访问；
- 数据库访问；
- 文件读写题；
- 复杂单元测试框架；
- 长时间运行程序；
- 自动代写答案。

验收标准：

- 能创建一个 Python 基础输入输出题；
- 学生能提交单文件代码或粘贴代码；
- 系统能运行固定测试用例并捕获 `stdout` / `stderr`；
- 系统能区分正确、错误、运行异常和超时；
- 教师能复核最终得分和反馈；
- 记录至少一种自动错误标签和一种教师修正标签。

### Phase 10: Learning Error Annotation Seed / 第十阶段：学习错误数据标注开端

目标：

- 在 SQL 和 Python 基础题批阅过程中记录学习错误数据；
- 保存自动识别错误类型；
- 保存教师修正后的错误类型；
- 标记是否需要后续辅导；
- 标记是否可作为脱敏样本进入教学错误数据集。

设计原则：

- 数据标注不是为了监控学生，而是为了帮助教师理解常见错误、优化导学案和改进教学；
- 公开仓库不得包含真实学生数据；
- 案例材料中只能使用演示数据或脱敏数据；
- 数据集建设是后续拓展方向，V0.2 只做开端。

验收标准：

- SQL 批阅结果中可以记录基础错误类型；
- Python 原型批阅结果中可以记录基础错误类型；
- 教师可以修正错误类型和反馈；
- 演示数据可以展示“常见错误统计 / 教师修正反馈”的雏形。

## 8.2 Error Type Tags / 错误类型标签

### 8.2.1 Python Error Tags / Python 错误标签

- `SyntaxError`：语法错误；
- `NameError`：变量未定义；
- `TypeError`：类型错误；
- `ValueError`：值错误；
- `IndexError`：索引错误；
- `ZeroDivisionError`：除零错误；
- `Timeout`：运行超时；
- `WrongAnswer`：答案错误；
- `FormatError`：输出格式错误；
- `LogicError`：疑似逻辑错误；
- `FunctionCallError`：函数调用错误；
- `ParameterError`：形参与实参理解错误；
- `InputOutputError`：输入输出理解错误。

### 8.2.2 SQL Error Tags / SQL 错误标签

- `SqlSyntaxError`：SQL 语法错误；
- `TableNameError`：表名错误；
- `ColumnNameError`：字段名错误；
- `ConditionError`：条件筛选错误；
- `OrderByError`：排序错误；
- `AggregationError`：聚合错误；
- `GroupByError`：分组错误；
- `JoinError`：连接错误；
- `WrongAnswer`：结果错误；
- `FormatError`：结果格式错误。

## 8.3 Confirmed Python MVP Decisions / Python MVP 已确认决策

Python 基础题批阅 MVP 的实施边界已确认：

1. 只演示 1-2 道基础题，不扩展题型。
2. 题目一：`input + if` 判断，例如输入成绩，判断是否及格。
3. 题目二：`for` 循环求和，例如输入 `n`，计算 `1` 到 `n` 的和。
4. 教师标注采用“主错误类型单选 + 教师补充说明文本”。
5. V0.2 不实现多标签错误标注。
6. `can_enter_dataset` 默认 `false`，只有教师手动勾选后才允许进入脱敏教学错误数据集。

这些确认项不得扩大 Python MVP 范围，也不得影响 SQL 主线交付。

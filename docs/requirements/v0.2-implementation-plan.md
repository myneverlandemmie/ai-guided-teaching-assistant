# V0.2 Implementation Plan / V0.2 实施计划

## 1. Purpose / 文档目的

本文件用于规划“智学导评 V0.2”的实施步骤，作为后续 Codex 施工、Git 提交、案例材料整理和阶段验收的依据。

This document defines the implementation plan for V0.2 of the AI Guided SQL Assessment Platform. It will guide Codex development, Git commits, case material preparation, and staged acceptance.

## 2. Current Version Goal / 当前版本目标

V0.2 的目标是在半个月内完成一个可演示、可部署、可申报案例的教学闭环系统。

核心主线为：

- 课程计划上传；
- 自动拆解课次；
- 教师上传课次材料；
- AI 生成知识主干、小测题、分层导学案；
- 学生查看导学案；
- 学生提交 SQL 作业；
- 系统自动批阅；
- 教师复核；
- 学生查看反馈；
- 系统生成学习总结。

V0.2 focuses on SQL / MySQL teaching. Python grading and OCR screenshot correction are not part of the core scope.

## 3. Development Environment / 开发环境

当前施工环境采用：

- 开发施工：WSL / Ubuntu；
- 浏览器测试：Windows；
- 案例演示：阿里云 ECS；
- 教师本地体验：Windows 单机模式；
- 真实课堂使用：教师或学校私有部署。

## 4. Implementation Phases / 实施阶段

### Phase 1: Documentation and Project Skeleton / 第一阶段：文档与项目骨架

目标：

- 建立项目英文目录结构；
- 建立双语 Markdown 文档规范；
- 初始化 Git 仓库；
- 明确 V0.2 功能边界；
- 明确三层使用模式；
- 准备 Codex 施工提示词。

验收标准：

- `git status` 显示工作区干净；
- `README.md`、`docs/requirements/v0.2-scope.md`、`docs/requirements/three-tier-usage-model.md` 已完成；
- `docs/prompts/codex-build-prompt.md` 可用于 Codex 施工。

### Phase 2: Course Plan Import / 第二阶段：课程计划导入

目标：

- 支持上传 `.xlsx` 授课计划；
- 解析周次、课次、学时、教学内容、教学用具、作业、备注；
- 从教学内容中提取课次编码与课次标题；
- 展示解析预览表；
- 支持教师确认、编辑或跳过课次；
- 将确认后的课次保存到数据库。

验收标准：

- 能上传样例授课计划；
- 能解析出 28 个计划课次；
- 能在页面中查看解析结果；
- 能确认生成正式课次。

### Phase 3: User, Class, and Demo Accounts / 第三阶段：用户、班级与演示账号

目标：

- 实现教师登录；
- 创建“演示班级”；
- 创建演示学生账号；
- 预留正常班级和学生账号管理功能。

验收标准：

- 教师能登录；
- 能查看演示班级；
- 能看到演示学生列表。

### Phase 4: AI Generation Workflow / 第四阶段：AI 生成链路

目标：

- 封装统一 AI 服务；
- 支持 DeepSeek V4 Flash 默认调用；
- 支持 DeepSeek V4 Pro 备用；
- 支持 Mock AI 模式；
- 生成知识主干；
- 生成三层小测题；
- 生成 A/B/C 分层导学案；
- 所有 AI 输出必须可编辑、可保存、可追溯。

验收标准：

- 无 API Key 时可用 Mock AI 模式演示；
- 有 API Key 时可调用真实模型；
- 教师可以编辑 AI 生成内容；
- 教师确认后才能发布给学生。

### Phase 5: SQL Assignment and Grading / 第五阶段：SQL 作业与自动批阅

目标：

- 教师创建 SELECT + WHERE 作业；
- 学生提交 SQL；
- 系统执行 SQL；
- 支持 SQLite 兼容演示模式；
- 支持 SELECT、WHERE、AS、简单计算字段；
- 生成初步批阅结果。

验收标准：

- 学生能提交 SQL；
- 系统能判断正确、错误和语法异常；
- 教师能查看系统初评结果。

### Phase 6: Teacher Review and Student Feedback / 第六阶段：教师复核与学生反馈

目标：

- 教师查看学生提交；
- 教师修改得分和评语；
- 教师确认发布反馈；
- 学生查看最终反馈。

验收标准：

- 自动批阅结果不会直接作为最终结果发布；
- 教师确认后学生才能看到反馈。

### Phase 7: Learning Summary / 第七阶段：学习总结

目标：

- 汇总学生小测、作业提交、批阅结果和教师反馈；
- 生成学习总结；
- 教师可编辑后发布。

验收标准：

- 每个演示学生可生成一份学习总结；
- 学习总结语言具体、温和、可执行。

### Phase 8: Deployment and Case Materials / 第八阶段：部署与案例材料

目标：

- 完成阿里云 ECS 演示部署；
- 准备 Windows 单机体验说明；
- 准备 Linux 私有部署说明；
- 准备 GitHub 开源发布说明；
- 准备 8 分钟案例视频脚本。

验收标准：

- 云端演示系统可访问；
- 本地演示路径有文档；
- 案例材料目录完整。

## 5. Out of Scope / 暂不施工内容

V0.2 不实现：

- 完整 Python 自动批阅；
- OCR 拍照纠错；
- 大规模外部教师真实班级试用；
- 复杂 Vue / React 前端；
- GPU 本地模型部署；
- 与学习通等平台深度对接。

## 6. Git Rules / Git 规则

每完成一个稳定阶段，应提交一次 Git commit。

建议提交信息：

- `docs: add v0.2 implementation plan`
- `docs: add course plan import design`
- `feat: implement course plan parser`
- `test: add course plan parser tests`

施工过程中，Codex 每完成一个可验证小任务，也应提交一次。

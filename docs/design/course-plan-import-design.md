# Course Plan Import Design / 课程计划导入设计

## 1. Purpose / 文档目的

本文档用于说明“课程计划上传与自动拆解课次”模块的设计方案。

该模块是智学导评 V0.2 的入口功能之一。教师上传整门课程的授课计划 Excel 后，系统应自动解析周次、课次、学时、教学内容、教学用具、作业与备注，并生成可预览、可编辑、可确认的课次列表。

This document defines the design of the course plan import module. The module allows teachers to upload a course plan spreadsheet and convert it into editable planned lessons.

## 2. Role in V0.2 / 在 V0.2 中的位置

课程计划导入模块位于整个教学流程的最前端。

流程关系如下：

- 教师创建课程；
- 教师上传授课计划 Excel；
- 系统解析授课计划；
- 系统生成课次预览；
- 教师确认课次；
- 系统批量创建正式课次；
- 后续教案、PPT、知识主干、小测题、导学案和 SQL 作业均挂接到具体课次。

该模块的目标不是替代教师制定课程计划，而是把教师已有的授课计划转化为系统可使用的数据结构。

## 3. Input File / 输入文件

V0.2 优先支持 `.xlsx` 格式的授课计划文件。

当前样例文件为：

- `2025-2026第2学期数据库应用与数据分析授课计划.xlsx`

该文件可作为第一阶段开发与测试样例。

## 4. Expected Columns / 预期字段

V0.2 先支持固定格式的 Excel 授课计划。系统应优先识别以下字段：

| 字段名称 | 含义 | 是否必需 | 说明 |
|---|---|---|---|
| *周次 | 周次 | 是 | 用于标记课次所在教学周 |
| *课次 | 课次序号 | 是 | 用于标记本课程中的第几次课 |
| 学时 | 学时数 | 是 | 通常为 2 或 4 |
| 教学内容(课堂教学，课带实验) | 教学内容 | 是 | 主要用于解析课次编码与课次标题 |
| 教学用具 | 教学资源 | 否 | 可保存为课次资源说明 |
| 作业 | 作业要求 | 否 | 可作为默认作业提示 |
| 备注 | 备注 | 否 | 保存教学补充说明 |

如果字段名称略有差异，V0.2 可以先提示教师“格式不匹配”，不要求自动兼容所有教务模板。

## 5. Parsing Rules / 解析规则

### 5.1 Basic Row Parsing / 基础行解析

系统应逐行读取 Excel 中的有效教学行。

有效行应至少包含：

- 周次；
- 课次；
- 学时；
- 教学内容。

如果某一行缺少教学内容，系统可以跳过该行，或在预览中标记为“待教师确认”。

### 5.2 Lesson Code Parsing / 课次编码解析

教学内容中可能包含类似以下格式：

- `0101-MySQL概述`
- `0401-简单查询`
- `0502-条件查询`
- `0801-视图`

系统应尝试从教学内容开头解析课次编码。

解析规则建议：

- 如果教学内容以 4 位数字开头，则将其识别为 `lesson_code`；
- 如果 4 位数字后存在 `-`、`—`、`：`、空格等分隔符，则分隔符后的内容识别为课次标题；
- 如果无法识别课次编码，则 `lesson_code` 留空，课次标题使用教学内容前若干字符生成。

### 5.3 Lesson Title Parsing / 课次标题解析

课次标题优先从教学内容中提取。

示例：

| 原始教学内容 | lesson_code | lesson_title |
|---|---|---|
| 0401-简单查询 | 0401 | 简单查询 |
| 0502-条件查询 | 0502 | 条件查询 |
| 0801：视图 | 0801 | 视图 |
| MySQL 数据库概述 | 空 | MySQL 数据库概述 |

如果教学内容较长，系统可以在预览页面显示完整原文，同时生成一个简短标题供教师修改。

## 6. Output Data / 输出数据

解析后，系统应生成 planned lesson 数据。

建议字段如下：

| 字段名 | 含义 |
|---|---|
| course_id | 所属课程 ID |
| source_upload_id | 来源上传记录 ID |
| week | 周次 |
| lesson_no | 课次序号 |
| hours | 学时 |
| lesson_code | 课次编码 |
| lesson_title | 课次标题 |
| content_raw | 原始教学内容 |
| tools | 教学用具 |
| homework | 作业 |
| notes | 备注 |
| status | 待确认 / 已确认 / 跳过 |

## 7. Preview Page / 解析预览页面

系统不应在上传后直接创建正式课次，而应先展示解析预览页面。

预览页面应包含：

- 周次；
- 课次；
- 学时；
- 课次编码；
- 课次标题；
- 原始教学内容；
- 教学用具；
- 作业；
- 备注；
- 状态；
- 操作按钮。

教师应能够进行以下操作：

- 修改课次标题；
- 修改备注；
- 修改作业提示；
- 跳过某一课次；
- 恢复被跳过的课次；
- 确认全部有效课次；
- 单独确认某一课次。

## 8. Confirmation Flow / 确认流程

推荐流程如下：

1. 教师上传授课计划；
2. 系统保存原始文件；
3. 系统解析 Excel；
4. 系统生成 planned lessons；
5. 教师进入预览页面；
6. 教师检查并修改解析结果；
7. 教师点击“确认生成课次”；
8. 系统将已确认的 planned lessons 写入 lessons 表；
9. 系统跳转到课次列表页面。

## 9. Error Handling / 异常处理

### 9.1 File Type Error / 文件类型错误

如果教师上传的不是 `.xlsx` 文件，系统应提示：

“当前仅支持 .xlsx 格式的授课计划，请重新上传。”

### 9.2 Missing Required Columns / 缺少必要字段

如果缺少周次、课次、学时或教学内容字段，系统应提示：

“授课计划格式不符合当前版本要求，请检查表头字段。”

### 9.3 Empty File / 空文件

如果 Excel 中没有可解析的有效教学行，系统应提示：

“未识别到有效课次，请检查授课计划内容。”

### 9.4 Partial Parse Failure / 部分解析失败

如果部分行无法解析，系统不应整体失败，而应在预览页面标记：

“该行需要教师确认。”

### 9.5 Duplicate Import / 重复导入

如果同一课程已经导入过授课计划，系统应提示教师选择：

- 覆盖原有计划；
- 新增导入记录；
- 取消本次导入。

V0.2 可以先实现“新增导入记录”，暂不自动覆盖。

## 10. Storage Design / 存储设计

建议至少包含两类数据表：

### 10.1 course_plan_uploads / 授课计划上传表

用于保存上传记录。

字段建议：

| 字段名 | 含义 |
|---|---|
| id | 上传记录 ID |
| course_id | 所属课程 ID |
| original_filename | 原始文件名 |
| file_path | 文件保存路径 |
| parsed_status | 解析状态 |
| error_message | 错误信息 |
| created_at | 上传时间 |

### 10.2 planned_lessons / 计划课次表

用于保存解析后的课次预览数据。

字段建议：

| 字段名 | 含义 |
|---|---|
| id | 计划课次 ID |
| course_plan_upload_id | 来源上传记录 ID |
| course_id | 所属课程 ID |
| week | 周次 |
| lesson_no | 课次序号 |
| hours | 学时 |
| lesson_code | 课次编码 |
| lesson_title | 课次标题 |
| content_raw | 原始教学内容 |
| tools | 教学用具 |
| homework | 作业 |
| notes | 备注 |
| status | 待确认 / 已确认 / 跳过 |

## 11. Testing Requirements / 测试要求

第一阶段应至少完成以下测试：

- 能读取样例 `.xlsx` 文件；
- 能识别预期表头；
- 能解析 28 个计划课次；
- 能提取 `0401-简单查询` 中的课次编码与标题；
- 能处理缺少课次编码的教学内容；
- 能跳过空行；
- 能在字段缺失时返回明确错误；
- 能生成可供页面展示的 planned lessons 列表。

## 12. Codex Construction Requirements / Codex 施工要求

Codex 第一阶段施工时，应优先实现以下内容：

1. 新增课程计划解析服务；
2. 使用 openpyxl 读取 `.xlsx` 文件；
3. 将字段识别、行解析、课次编码解析拆成独立函数；
4. 为解析函数编写单元测试；
5. 暂时不实现复杂前端；
6. 可先提供命令行测试脚本或简单页面；
7. 解析结果必须可追溯到原始上传文件；
8. 不要扩展到 Python 批阅或 OCR 功能。

## 13. Acceptance Criteria / 验收标准

本模块完成后，应满足：

- 教师可以上传样例授课计划；
- 系统可以解析出计划课次；
- 教师可以在页面中看到解析结果；
- 教师可以确认、编辑或跳过课次；
- 确认后的课次可以进入正式课次列表；
- 后续知识主干、小测题、导学案和作业可以挂接到这些课次上。
